## Interfaces and architecture

- `bootstrap.open_app(settings: Settings) -> AppHandle` is the shared entry point.
  Its returned handle supplies `.service`, `start_executor() -> bool`, `close() -> None`.
- Export a planner and handler registry from `pipeline/registry.py`. Implement the
  frozen `plan(store, job, stage) -> list[StepSpec]` and `async run(ctx) -> StepResult`.
  Separate modules by existing stage responsibility when useful; avoid a monolith.
- Services encode scopes in `Job.scope`: `source_ids`, `occurrence_ids`, or `filter`.
  Options contain refresh/max_occurrences, retrieval budget,
  export formats/selection/project_revision, or sender/language/group_by_author.
  Read the merged service implementation to consume the exact keys it writes.
- `StepResult.commit(store)` executes synchronously inside the executor's same
  `BEGIN IMMEDIATE` transaction as the succeeded step. It returns an output reference.
  Do not perform async I/O or open a second thread transaction inside this callback.
- Reads and blocking PDF/file work in async handlers use worker threads where needed.
  No database transaction may span an await. Capture a consistent immutable input
  view; validate revisions again in the final write transaction.

## Requirements

1. Composition: initialize RC_HOME directories, Database/migrations, SqliteStore,
   SqliteJobQueue, concrete adapters, RefCollectorServiceImpl, executor and planner.
   Real CLI and MCP use this root without monkeypatches. `open_app` alone must not
   contact providers or start work. `start_executor` takes/polls the existing lock;
   repeated start/close are safe. Close resources on success and initialization failure.
2. Avoid deleting another process's active temp files. Startup cleanup/orphan indexing
   must coordinate with executor ownership; close stops background activity before
   closing database connections. Test two handles on the same file-backed RC_HOME.
3. Build provider clients per job from `job.snapshot`, including allowlist, email,
   network mode, policy versions and versions. Do not substitute current settings on
   resume or share async clients across event loops. Close clients deterministically.
   Provide the synchronous service `identity_factory(snapshot)` without leaking clients.
4. Plan stages when reached (D-22). An extract→resolve→discover job sees new occurrences.
   Source and occurrence scopes remain project-scoped. Resolve only eligible/new or
   invalidated occurrences unless refresh semantics require a fresh result. Excluded references
   are not processed. Honor caps and explicit user scope; never silently widen scope.
5. Fingerprints include every output-changing input: subject/project identity, source
   bytes/sections/revisions, edited citation, relevant candidate/rejection state, locks,
   overrides/source ranks, effective work/access/local-copy state, stage options, target
   project revision, and artifact choices as appropriate. Executor handles snapshot hash.
   Reused outputs must remain valid and job results must still link to reused subjects.
   Do not depend on cross-project reuse; D-27 forbids it.
6. Extraction: read granted source bytes (or decode stored pasted text), call the adapter
   using selected sections, create ordered occurrences with raw text/spans/warnings,
   record adapter/version and source state. Link produced occurrence IDs to the job.
   Re-extraction must preserve edits/reviews or use explicit predecessor/supersession
   rules, never silently duplicate active occurrences. Splits/merges resolve only successors.
7. Resolution: persist ranked candidates with features/reasons/provider evidence,
   rejections and result state. No unattended `accepted_user`. On automatic acceptance,
   deduplicate ProjectWork by canonical DOI/OpenAlex keys within this project only.
   Two source occurrences keep separate identities linked to one work (AT-18).
   Use `merge_work_metadata(...) -> ProjectWork` to persist metadata and source ranks
   together; locks/locked overrides survive refresh. Preserve explicit decisions and
   handle approval staleness per domain/rules and actual occurrence revision.
8. Discovery: run once per accepted work in scope, persist the returned AccessCheck
   through `add_current`, retain superseded history, and update affected occurrences'
   discovery/classification/time without changing identity. Propagate sources_failed
   and scoped wording. Never invent restriction or approval evidence.
9. Retrieval: evaluate project/work-specific local copies before any network. All five
   checks pass: persist usable copy and satisfied_by_local_copy, no download. A failed
   copy retains failed check and proceeds normally. Apply snapshotted version policy,
   eligible locations and budget; use the secured default ProviderHttpClient/DefaultRetriever.
   Persist returned WorkFile/state/reasons, hashes and grants; wrong/supplement copies
   remain needs_review. Preserve classification. Check cancellation at I/O boundaries.
10. Cancellation and races: no committed partial entity set. Discard uncommitted
    output when cancelled; existing completed files remain. FileStore may stage bytes
    before commit; avoid visible rows/grants for cancelled output where possible and
    retain orphan recovery semantics. A concurrent edit must not be overwritten by
    a handler's stale captured input. Test rollback and revision conflict behavior.
11. Export: collect project, all selected occurrences, effective work, decision,
    current access and files from one SQLite read transaction. Render the frozen
    selection against the requested revision; reject stale export revisions before
    publishing artifacts. Build manifest from actual bytes/hashes, persist artifact
    descriptors with exact revision/job links and atomic file publication. Include
    verified PDF bytes only through grants and collision-safe export filenames.
12. Drafts: gather scoped rows consistently, honor service access preconditions and
    accepted identities, then render sender/language/grouping using DefaultDraftRenderer.
    Save text/eml artifacts, recipients blank. Do not send messages or add send capability.
13. Every committed output mutation increments project/occurrence revisions as required,
    includes audit provenance from job origin or automation, and remains one executor
    commit with step completion. Job results expose occurrence/artifact IDs through
    the existing service queries. Preserve history and project isolation.
14. Offline integration tests exercise the real root, service, executor, file-backed
    SQLite and renderers. Inject fake provider HTTP/adapter factories only at owned
    composition seams. No live sockets, new dependencies, unrelated fixes or changes
    to frozen/public contracts. Identify exact blockers rather than fake completion.
